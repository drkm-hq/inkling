These are unified diffs for git apply. The three projects have separate patch
sequences. Use a working checkout of the listed contribution tip for each project.
The original review snapshot and upstream checkouts were preserved.

The prerequisite correctness patches are included in prerequisites/. They are
byte-for-byte copies from inkling-review-fixes-2026-10-31. Skip a prerequisite
only if it has already been applied. The snapshot README/benchmark patch is not

HOW TO APPLY

Run these commands from each target checkout for each patch in its sequence,
substituting the patch's absolute path:

  git apply --check --whitespace=error-all /absolute/path/to/patch
  git apply --whitespace=error-all /absolute/path/to/patch

All three sequences were checked and applied to fresh archives of the exact
contribution tips above, including the prerequisite patches. These checks do
not establish compatibility with a newer upstream tip. Rebase and rerun the
targeted checks when changing the base.

BUILD AND TEST PREREQUISITES

The Metal paths require a supported Apple Silicon Mac and Metal availability.
For K1, use the contribution's documented CMake/C++ and Apple Metal build tools.
For K2/K4, use Python 3.11 or newer with the dependencies declared by the target
checkout, including its MLX runtime, and pytest for K4. Run tests from the source
checkout so imports resolve to the patched files. GPU work and builds should be
serialized when collecting comparable performance measurements.

Targeted K1 checks after rebuilding:

  cmake -S . -B build-inkling-perf -DCMAKE_BUILD_TYPE=Release -DGGML_METAL=ON -DLLAMA_BUILD_TESTS=ON
  cmake --build build-inkling-perf --target test-backend-ops
  build-inkling-perf/bin/test-backend-ops -b MTL0 -o SSM_CONV,SSM_CONV_BIAS_SILU

Targeted K2 checks:

  python -m unittest tests.test_inkling tests.test_inkling_gate_up tests.test_models.TestModels.test_inkling_mm_model

Targeted K4 checks:

  python -m pytest -q mlx_vlm/tests/test_inkling_sconv_pair.py mlx_vlm/tests/test_inkling_convnorm.py mlx_vlm/tests/test_inkling_fast_path.py mlx_vlm/tests/test_inkling_kernel_gates.py

These are focused regression commands. Application instructions and test
coverage do not establish a whole-model throughput improvement; measurement
results are reported separately.

OPTIONAL K1 EXPERIMENT

The experimental/ patches are separate from the main sequence. A whole-model
performance gain has not been established for this combination. Apply them
only when evaluating this experiment, after the main K1 patch 01:

  experimental/02-metal-relative-projection-fusion.patch
  experimental/03-inkling-expand-relative-input.patch

The first patch fuses a supported relative-projection CONT/MUL_MAT sequence;
the second explicitly expands the relative input before that sequence in the
Inkling graph. Their application order was checked on the same K1 base.
The first patch also adds graph-order boundary cases to
tests/test-metal-graph-optimize.cpp. Rebuild and run test-metal-graph-optimize;
rebuild test-backend-ops and select the dedicated CONT_MUL_MAT test cases:

  build-inkling-perf/bin/test-backend-ops test -b MTL0 -o CONT_MUL_MAT

The second patch also needs an actual Inkling model check for activation and
output agreement; operator tests alone do not exercise graph ordering.
