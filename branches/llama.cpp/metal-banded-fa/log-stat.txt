ggml : q_offset for the banded flash attention (proposal for #25731)

ggml_flash_attn_ext_banded takes the kv index of the first query
(op_params[5]) instead of deriving it from n_kv - n_q. CPU reads it, the
CUDA scalar kernel takes it as an argument, the CUDA MMA path carries it in
its unused m0 slot, Metal reads it. The model passes the cache's 256-padded
views and the raw KQ mask with q_offset = pos_max + 1 - n_tokens. Tests:
padded KV and non-tail offsets. CUDA paths verified on an H100.

tests : banded flash attention cases

The helper gains a sliding window independent of the band, a batch
dimension with a shared or per-batch table, the n_kv_max hint and input
magnitudes. Cases at the Inkling-Small geometry (32/8 heads x 128, E 1024
and 512) for every kernel family: block boundaries, band edges, no mask,
window, heads, KV and table types, batch, strided rows, 1M keys; perf cases
next to the plain op.

Tolerance: the CUDA MMA kernel accumulates VKQ in f16, so its error grows
with the visible keys (H100: NMSE 1.1e-6 .. 1.2e-5 for the f16 prefill
cases up to 8192 keys, 4.2e-5 at 32K); the Metal kernels and the CPU
reference keep f32 accumulators (observed 1e-13 .. 7e-8 for f16, f32 and
quantized KV, 2e-5 for bf16 KV, 4e-5 at 1M keys). Bound: 1e-4 up to 8192
keys, 5e-4 above, 1e-4 for bf16 KV.
