ggml : explicit q_offset for the banded flash attention

The banded op derived the position of the queries from n_kv - n_q, which
forced the model to pass K/V/mask views of exactly pos_max + 1 rows. Those
views are rarely aligned to the kernel block sizes, so on Metal the
prefill ubatches fell off the tensor-API kernel onto the half8x8 kernel
plus a pad pass (1.5x the time at 8K, measured in test-backend-ops), and
the mask had to be re-copied per layer.

ggml_flash_attn_ext_banded now takes q_offset (op_params[5]), the kv index
of the first query: rel_dist = q_idx + q_offset - kv_idx. Honoured by the
CPU op, the CUDA scalar kernel (kernel argument), the CUDA MMA path (the
banded ABI carries it in the unused m0 slope, exact below 2^24) and Metal.

The model passes the cache's own 256-padded n_kv views and the KQ mask as
they are (the padded cells are masked) with q_offset = n_kv_flash -
n_tokens, so every prefill ubatch takes the aligned kernel and the
per-layer ggml_cont of the mask view is gone.

test-backend-ops gains a kv_pad parameter for the banded cases: masked rows
past the logical n_kv with the band anchored by q_offset.

metal : add GGML_OP_FLASH_ATTN_EXT_BANDED

Run the banded (relative-position bias) flash attention of the TML Inkling
models on the GPU instead of falling back to the CPU scalar path.

The bias is a second additive score term next to the KQ mask, so the three
existing flash attention kernel families (half8x8 simdgroup, Metal 4 tensor
API, vec) gain one buffer (the bias table), one function constant pair
(has_rel, rel_type: F32/F16/BF16 read as raw bits) and the kargs needed to
address the table: for a query row iq and key ik the term is
rel[iq + q_off - ik] when 0 <= dist < rel_extent and zero otherwise, with
q_off = n_kv - n_q as the op defines it. Blocks outside the band skip the
gather with a uniform test, the kv-pad path keeps the absolute key index,
and the sparse vec path uses the gathered key index.

The host side reuses everything else: the dequant-to-F16 pre-pass for
quantized KV, the pad/blk/reduce auxiliaries and the scratch sizing
(ggml_backend_metal_buffer_type_get_alloc_size now covers the banded op).
supports_op mirrors the plain op plus the bias table checks.
