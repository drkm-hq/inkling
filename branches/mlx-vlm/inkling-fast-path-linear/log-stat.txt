SlidingWindowKVCache.trim rolled the offset back by any amount while
is_trimmable() stayed True, so a trim deeper than the keys compaction had

Add bounded, temporally ordered sliding-window KV caches

SlidingWindowKVCache keeps the last max_size - 1 keys of a sliding-window
layer plus a slack buffer, in temporal order, and compacts in place every
buffer_size tokens; the update returns one contiguous view the model can
slice to its exact window. RotatingKVCache cannot serve layers that build
their own attention bias from query/key distance because it returns the
ring out of temporal order once it wraps, and the unbounded KVCache that
such layers use today grows with the whole context although only the window
is ever read. The cache is trimmable for speculative rollback, snapshots
through state/meta_state (prefix cache, from_state), reports a windowed
memory profile, and converts to BatchSlidingWindowKVCache for continuous
batching: the batched form shares BatchKVCache's left-padded column layout,
drops the leading columns no row can see any more (shifting left_padding
with them), defers compaction while right padding is pending so finalize()
can roll rows first, and supports extract/merge/extend/filter/trim.
BufferedRotatingKVCache's state setter no longer requires offset to exist,
which from_state() violated by assigning state before meta_state. Tests
check the window against an unbounded reference over several update
schedules, the memory bound over a long decode, trim, snapshot round trips,
prefix-reuse refusal after eviction, and per-row equality of the batched
cache with single-row caches including right-padded prompts.

Evaluate eagerly loaded parameters in bounded chunks

load_model_weights evaluated every parameter of an eagerly loaded model in
one mx.eval, which runs as a single Metal command buffer. For an 80+ GB
checkpoint (Inkling-Small 2-bit is 82 GiB) that command buffer exceeds the
GPU watchdog budget on a 128 GB M5 Max and the load aborts with

still takes exactly one eval. Tests spy on mx.eval to check that every
parameter array is evaluated exactly once under small chunk bounds, that an
eager load_model_weights covers all loaded parameters, and that lazy loads
still evaluate nothing.
